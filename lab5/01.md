# CPU Architecture

CPU architecture defines the **instruction set** the CPU executes, the register set, and the native word size (most importantly, register width, and therefore, memory addressing).

| Names                      | A.K.A                | Typical Devices                                              |
| :------------------------- | :------------------- | :----------------------------------------------------------- |
| `x86_64`, `amd64`, `x64`   | 64-bit Intel/AMD     | Modern Desktop PCs, Laptops, Servers, and Intel Macs.        |
| `i386` / `i686` / `x86`    | 32-bit Intel/AMD     | Older PCs and legacy systems                                 |
| `arm64` / `aarch64`        | 64-bit ARM  (ARMv8+) | Modern Smartphones, Apple Silicon Macs, Raspberry Pi 3/4/5 (64-bit OS) |
| `armhf` / `armv7l` / `arm` | 32-bit ARM  (ARMv7+) | Older Smartphones/Tablets, Raspberry Pi (32-bit OS), Embedded Systems |

## Notes

- Intel designed `x86` architecture and AMD adopted it.
  - AMD then designed the 64-bit extension (`x86-64`) and Intel adopted it.
  - `x86` refers to the family of Intel CPUs whose model numbers ended in 86 (`8086 -> 80186 -> 80486 -> Pentium`).

- Intel/AMD CPUs are generally considered CISC (Complex Instruction Set Computers)
  - ARM however follows a RISC (Reduced) philosophy (smaller instruction set, more work for software, generally more power-efficient).

- QEMU emulates (can run VM guests) all of these architectures, and [many others](https://wiki.qemu.org/Documentation/Platforms).

  - [Lima](https://lima-vm.io/) (among many other projects) provide simpler interface for *mere* humans to work with QEMU.
  - In this lab, we discuss buffer overflow **for `x86` architecture**. To follow along, it's necessary to use an `x86` machine (either your hardware or a VM with hardware emulation).

- It's also important to understand package naming when compiling/obtaining/releasing software packages (e.g., [ripgrep releases](https://github.com/BurntSushi/ripgrep/releases)). A dash-separated format is typically used: `<app>-<semver>-<arch>-<vendor>-<sys>-<abi>.<ext>` 
  - `arch`: CPU instruction set (e.g., `x86_64`, `aarch64`, `armv7`, `riscv64`).
  - `vendor`: target hardware if relevant (e.g., `pc`, `apple`, `nvidea`, or `unknown`).
  - `sys`: OS kernel/environment (e.g., `linux`, `windows`, `darwin`, `ios`).
  - `abi`: Application Binary Interface or C stdlib (e.g., `gnu`, `musl`, `eabi`, `msvc`).
  - `ext`: executable, compressed, or installer package (e.g., `zip`, `.tar.gz`, `exe`, `.msi`, `.deb`, `.dmg`)
