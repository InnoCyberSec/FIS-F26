# Token-Based Authentication

After you demolished the app security in previous exercises, the admin decided to implement the secure token-based authentication (with JWTs) and use SHA-1 hashes instead of MD5 for verifying admin password. Moreover, they added a 1s delay to their endpoints to prevent you from spamming their service.

> Essential reading: [How JWTs work?](https://www.geeksforgeeks.org/web-tech/json-web-token-jwt/)

![img](https://media.geeksforgeeks.org/wp-content/uploads/20250908173351627043/client.webp)

## Server Logic

1. Anyone can request a token by making a request `GET /get_token?password=<REDACTED>`
2. Only the admin token (obtained by supplying the correct password) contains the payload `{admin: True}` in the body.
3. Only the admid can `GET /admin?token=<JWT>` with a valid signed token.
